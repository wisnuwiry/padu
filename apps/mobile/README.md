# Padu Mobile

Expo client for connecting to one or more remote Padu daemons from iOS and
Android.

## Run

From the repository root:

```sh
bun install
bun --filter @padu/mobile ios
bun --filter @padu/mobile android
bun --filter @padu/mobile web
```

## Native projects

`ios/` and `android/` are produced by prebuild and are gitignored. Treat them as
build output: don't hand-edit them, and don't expect changes to survive.

Regenerate them whenever the Expo SDK or React Native version changes, because a
native project generated by an older SDK keeps that SDK's launch code:

```sh
cd apps/mobile
npx expo prebuild --clean --platform ios
```

A stale project installs fine and then dies at launch with:

```
Application failed to launch: UIScene life cycle is required for apps built with this SDK.
```

SDK 58 moved iOS to the scene-based life cycle — `SceneDelegate.swift`
(subclassing `ExpoAppSceneDelegate`) plus a `UIApplicationSceneManifest` in
`Info.plist`. A project generated by SDK 57 has neither, and `bun --filter
@padu/mobile ios` only runs prebuild when `ios/` is *missing*, so it won't
refresh a stale directory for you.

## Native modules

This is the only tree that depends on Expo, and it stays that way: keep
`expo-*` packages in `apps/mobile`, never in `apps/web` or `apps/desktop`. A
native capability is platform-exclusive, so it needs no desktop or web
counterpart.

Install with the SDK's own pin, then declare the permissions the module needs
through its config plugin in `app.json`:

```sh
bunx expo install expo-camera
```

The QR scanner (`src/app/scan.tsx`) uses `expo-camera`. `app.json` declares its
iOS camera usage string and leaves audio recording off, so `RECORD_AUDIO` is
never added. Both the module and any plugin edit are invisible until the native
projects are regenerated — see [Native projects](#native-projects).

## Connect

In Padu Desktop, enable the remote daemon and copy its WebSocket address and
token. Add those values in the mobile app. Use `wss://` outside a trusted LAN
or private tailnet; the token grants full control of the daemon host.

Saved profile metadata stays in app storage. On iOS and Android, daemon tokens
are stored separately in the device keychain through Expo SecureStore.
